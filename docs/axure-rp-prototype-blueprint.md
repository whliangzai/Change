# Axure RP 页面重设计蓝图

## 1. 目标与边界

本蓝图用于制作 A 股短线量化验证系统的 Axure RP 桌面端交互原型，服务于数据治理、研究回测、日终验证和人工确认。原型应帮助用户看清当前状态、下一步和操作影响，而不是模拟交易终端。

- 默认画板：1440 px 宽桌面端；同步制作 390 px 窄屏查看稿。
- 用户：`USER`、`REVIEWER`、`ADMIN`；隐藏的入口不等于放行权限，原型需在操作后表现服务端校验结果。
- 业务红线：不出现自动下单、撤单、补单、资金划转或自动恢复风险状态；计划、模拟成交和人工实际成交必须单独表达。
- 已有视觉与交互基线见 `docs/frontend-page-effect-spec.md`；本蓝图不取代其色彩、间距、可访问性和安全规则。

   │  └─ 股票池与日线
   ├─ 研究
   │  ├─ 策略版本
   │  │  ├─ 创建策略草稿
   │  │  └─ 审核／发布确认
   │  ├─ 回测运行
   │  │  ├─ 新建回测（四步）

   │  └─ 报告与偏差
   ├─ 运营与人工确认

## 4. 全局框架与组件库

### 4.1 全局母版

| 母版 | 内容与规则 |
| --- | --- |
| `M-Header` | 系统名称、当前用户、角色标签、主题切换、退出；角色信息为只读。 |
| `M-Nav` | 按“观察、研究、运营与人工确认、管理”分组；当前页以文字和标识双重提示。 |
| `M-Compliance` | 固定表达“研究用途、人工确认、不会自动下单”的边界。 |
| `M-PageHeader` | 页面标题、用途说明、至多一个主操作；主操作与页面核心任务一致。 |
| `M-ToastOrState` | 页面内反馈条，不自动消失；支持信息、加载、成功、警告、失败、不可用。 |
| `M-ConfirmDialog` | 显示对象、当前状态、影响、必填备注和确认/取消按钮。 |
| `M-RightDrawer` | 用于质量明细、任务详情、版本差异；关闭后保留列表筛选与滚动位置。 |

### 4.2 基础组件

| 组件 | 状态 | 交互说明 |
| --- | --- | --- |
| 按钮 | 默认、悬停、禁用、提交中、成功/失败返回 | 提交中锁定重复点击；危险操作不得作为默认主按钮。 |
| 表单字段 | 默认、聚焦、已填写、字段错误、禁用 | 标签、格式说明和字段错误固定出现位置，不能仅依靠红色边框。 |
| 状态标签 | 可用、不可用、待处理、运行中、成功、失败、待审核、已确认、已跳过 | 颜色、文字和图标同时传达状态。 |
| 数据表格 | 初始加载、正常、无结果、失败、分页 | 标识、状态、时间保持可见；宽列在局部横向滚动容器内。 |
| 步骤条 | 未开始、当前、已完成、阻断 | 显示当前步骤名称与阻断原因，而非仅显示编号。 |
| 空状态 | 无数据、无筛选结果、依赖未满足 | 解释原因并提供唯一可执行下一步。 |

## 5. 核心流程与页面交互

### 5.1 运行总览（A-01）

首屏采用四个状态模块：数据可用性、风险与日报、研究运行、待办与人工确认。模块优先级由阻断程度决定：不可用或失败状态排在最前。

- 点击“查看数据批次”进入 A-02 并保留当天日期筛选。
- 日报不可用时显示原因，例如“尚未完成日终运行”，主入口变为“查看日终状态”。
- 待办只显示需要人工处理的数量和类型，不显示或暗示自动执行。

### 5.2 数据质量与行情导入（A-02、A-13）

- A-02：筛选区位于表格上方；点击某批次展开右侧抽屉，依次展示批次信息、质量结论、问题项、信息截点和下游可用性。
- A-13：使用四步步骤条：选择导入方式 → 填写来源与日期 → 预检查 → 提交并查看结果。
- 供应商导入必须先选择业务日期和 pilot/full 范围；`full` 在无人工授权证据时呈禁用状态，并说明“需先完成人工批准”。
- 提交后进入“已提交，正在排队”状态，提供“前往任务中心”，不提供伪造的进度百分比。

### 5.3 策略与回测（A-04 至 A-08）

- 策略版本页：采用“版本清单 + 当前版本详情”双栏布局；创建草稿、版本差异、审核决定分别作为独立动态面板，避免首屏堆叠多个表单。
- 审核或发布前打开确认面板，显示版本号、变更理由、参数差异、当前状态、审核备注和服务端可能拒绝的原因。
- 新建回测使用四步流程：选择可用数据批次 → 选择已发布策略 → 设置时间区间 → 核对并创建。
- 日期不满足 `start ≤ train_end < valid_end < oos_start ≤ end` 时，阻断在对应步骤，并用自然语言说明需要如何调整。
- 回测详情按“运行证据 → 绩效报告 → 模拟交易明细”排列；模拟交易始终标记为“研究模拟，不是委托或实际成交”。

### 5.4 日终、计划与人工成交（A-09 至 A-12）

- 执行日终使用四步流程：选择可用批次 → 选择已发布策略 → 设置业务日期与信息截点 → 核对并提交。
- 成功结果页展示候选数、风险拒绝数、生成的 T+1 人工计划数以及前往日报/计划确认的入口。
- 人工计划确认页采用“计划表格 + 审核抽屉”：抽屉必须展示标的、数量、模拟参考价、风险标签、版本、当前状态与审核备注。
- 审核决定只允许“确认计划”或“跳过计划”；提交后的成功文案为“已记录人工决定”，不可表述为“已下单”或“已成交”。
- 人工成交录入必须先加载可录入计划，再填写已发生的成交时间、数量、价格、费用和备注；部分成交需要明确填写未成交数量和原因。

### 5.5 管理与审计（A-14）

- 任务表格显示任务编号、来源、范围、交易日期、状态、尝试次数、质量结论、失败原因和完成时间。
- “请求重试”仅在任务满足重试条件时显示；确认弹窗写明“仅提交重试请求，最终可否执行由服务端决定”。
- 审计记录以只读表格呈现，长任务键和请求号可复制。

## 6. 页面状态与提示文案

每个异步区域均制作以下动态面板：加载、正常、空、不可用、无权限、失败、成功。

| 场景 | 原型文案 |
| --- | --- |
| 数据批次不可用 | “该批次尚不能用于回测或日终：质量检查未通过。请查看问题项并导入修正后的新批次。” |
| 未满足权限 | “你当前没有执行此操作的权限。请联系管理员，或返回可访问的页面。” |
| 回测日期校验失败 | “日期区间无法用于回测：训练结束日期需早于验证结束日期，验证结束日期需早于样本外开始日期。” |
| 任务处理中 | “任务已受理，正在后台处理。你可以离开本页，并在任务中心查看最终结果。” |
| 日终无候选 | “本次日终未生成候选或 T+1 人工计划。请核对数据覆盖、策略条件和风险限制；这不代表成交。” |
| 人工计划确认成功 | “已记录人工决定。该记录仅用于后续人工处理，不会自动发出交易委托。” |

## 7. Axure 交付规则

1. 每个页面使用 `M-Header`、`M-Nav`、`M-Compliance`、`M-PageHeader` 母版；页面不单独复制导航或合规文案。
2. 所有页面为 `1440 px` 桌面画板，基于 12 列栅格；额外提供关键页面的 `390 px` 窄屏稿。
3. 使用动态面板实现加载、空、失败、成功、无权限和确认弹窗；不要用多张静态图替代状态切换。
4. 每个可点击元件添加交互注释：触发条件、变化结果、权限前提、异常反馈和目标页面。
5. 用接近真实的模拟数据展示批次号、日期、状态、策略版本、任务键和风险原因；样例数据必须标识为“示例/模拟”。
6. 页面流应从登录、总览开始，可完整演示“导入 → 质量通过 → 策略发布 → 回测 → 日终 → 人工确认 → 人工成交录入”的主路径。

## 8. 原型验收清单

- [ ] 任何页面首屏都能在 5 秒内识别页面用途、当前状态与唯一主操作。
- [ ] 所有高风险操作展示对象、影响、备注与二次确认。
- [ ] 每个提交动作均有提交中、成功和失败状态，且防止重复触发。
- [ ] 数据质量、策略发布、回测、日终、计划确认和人工成交的概念没有混用。
- [ ] 不存在自动下单、撤单、资金划转或收益承诺的文案和交互。
- [ ] 权限不足、依赖未满足、无数据和系统失败均说明下一步处理方法。
- [ ] 桌面与窄屏稿均不存在文字截断、页面横向溢出或关键操作不可达。

# 前端页面效果规范

## 1. 目的、范围与术语

本规范定义 A 股短线量化验证系统的前端页面效果、交互反馈和验收标准。它服务于产品、设计、前端开发和测试，确保现有与新增页面在信息密度、风险表达和人工流程边界上保持一致。

本规范不改变服务端权限、审计、幂等或业务状态机；页面必须如实表达这些已有规则，不能以视觉或文案暗示自动下单、收益承诺或交易建议。

适用范围包括登录、运行总览、数据质量、行情导入、股票池、策略版本、回测、日终、日报、人工计划、人工成交、报告与管理审计。后续新增页面必须复用本规范，或先补充新的页面模板后再实现。

规则用语如下：

- **必须**：未满足不得合入或上线。
- **应当**：默认实现方式；偏离时应说明业务原因并在评审中确认。
- **可选**：在不破坏其他规则时可使用。

## 2. 用户任务与体验原则

系统面向研究、数据治理、回测复核和人工确认工作，不是交易终端。桌面端优先支持高频扫描、比较、筛选、复核和批量操作；移动端优先支持查看、筛选、审批、错误处理和关键状态确认。

页面应当遵守以下原则：

1. **先状态，后细节。** 数据质量、运行可用性、权限和风险应在用户进入任务前可见。
2. **先证据，后操作。** 发布、确认、跳过、重试等动作附近必须呈现对象、前提和影响。
3. **紧凑而不拥挤。** 用稳定的栅格、表格和字段分组提高扫描效率，不以装饰性卡片替代信息层级。
4. **研究边界清晰。** 涉及行情、回测、计划和成交的页面，必须保留相应的研究用途、模拟价或人工录入说明。
5. **失败可恢复。** 异步失败不只显示错误，应说明下一步可执行操作或需要的外部条件。

## 3. 全局视觉语言

### 3.1 色彩

颜色只表达系统语义，不能仅作装饰。现有变量可作为实现基准：

| 角色 | 建议值 | 用途 |
| --- | --- | --- |
| 系统框架 | `#102A43` | 顶部系统栏、品牌区 |
| 导航层 | `#173F5F` | 主导航背景 |
| 主操作 | `#185ADB` | 主要按钮、链接、键盘焦点 |
| 成功/可用 | `#16704A` | 数据可用、完成、校验通过 |
| 警告/关注 | `#F6C344` | 当前导航、风险提示、待关注状态 |
| 错误/阻断 | `#B42318` | 校验失败、不可用、危险操作反馈 |
| 页面背景 | `#F4F6F8` | 工作区底色 |
| 分隔线 | `#D9E0E7` | 表格、面板与控件边界 |

状态必须同时使用文字、图标或位置等非颜色线索；不得以红绿颜色单独传达通过、失败、涨跌或审批结果。

### 3.2 排版与间距

- 字体使用系统 UI 字体与 `Microsoft YaHei` 回退；正文默认 `14px/1.5`，数字和标识符使用等宽/表格数字能力。
- 页面标题为 `24px`，面板标题为 `16px` 左右，表头为 `12px`。
- 默认桌面主内容最大宽度为 `1200px`；数据密集研究页和股票池允许 `1440px` 宽版；外侧留白为 `20px`，移动端固定为 `16px`。
- 常规组件间距为 `12px`，面板内边距为 `16px`，表格单元格内边距为 `10px 11px`；控件高度为 `40px`，允许在关键操作处使用 `42-44px`。
- 面板圆角为 `8px`，控件圆角为 `6px`，状态标签使用胶囊圆角；不得使用渐变背景、装饰性光晕或营销式大幅留白。

### 3.3 信息密度与数字

- 数字列、金额、比例和日期列必须保持稳定宽度并右对齐；标的代码、名称和说明左对齐。
- 金额、数量、百分比和时间须使用统一格式、单位与精度；无数据使用 `--`，不得用空白误导为零。
- 长标识符、JSON 和审计请求号必须可复制，采用等宽字体，并以容器滚动而不是压缩文字处理。

## 4. 页面骨架与响应式

非登录页必须由系统头部、主导航、合规提示、主工作区和页脚组成。当前导航同时以文字状态和黄色底边标识。无权限的导航项必须隐藏，不得留下不可点击的占位项。

每个业务页必须包含以下顺序：

1. 页面标题区：`H1`、一句业务边界或数据来源说明，以及至多一个主操作。
2. 状态或前置条件区：当页面依赖权限、数据批次、策略版本或运行结果时，先显示其可用性。
3. 主工作区：按页面模板组织筛选、表单、表格、指标或审批内容。
4. 异步反馈区：结果、错误、请求号、审计线索或下一步入口紧邻触发动作。

桌面端使用 12 列栅格。概览指标最多三列；表单常规为三列，字段依赖或长文本跨满整行。小于 `900px` 时主导航切换为原生按钮控制的可键盘操作折叠菜单；小于 `700px` 时标题区与会话区纵向排列，表单改为单列，主操作应占满可用宽度。宽表、代码块和 JSON 必须使用局部横向滚动，页面整体不得横向溢出。

## 5. 组件与交互状态

### 5.1 按钮、链接与工具栏

- 每个标题区或工作区只能有一个视觉主按钮；其他动作使用次级按钮、文本链接或行级菜单。
- 主按钮用于创建、执行、提交等明确命令，不应用于刷新、关闭、返回或查看详情。
- 提交后按钮必须禁用并显示进行中状态，直到收到成功或失败结果，以防重复请求。
- 危险动作必须在操作前说明对象、影响和不可逆性；确认动作不得只依赖颜色或模糊文案。

### 5.2 表单与筛选

- 输入必须使用可见标签；必填、格式、范围、单位和示例应在字段附近表达。
- 前端校验错误放在字段附近，服务端业务错误放在表单顶部并回指相关字段；不得只弹出短暂提示。
- 筛选区位于表格前方，重置筛选时恢复初始列表状态；筛选结果应呈现条数、加载或无结果。
- 选择依赖数据批次、策略版本或权限的字段，未满足条件时必须禁用并说明原因。

### 5.3 表格、分页与详情

- 表头必须固定字段语义；可排序字段需呈现当前排序方向，非排序字段不可伪装成可点击控件。
- 行级操作不能挤压关键业务列；窄屏下优先保留标识、状态与时间，其他列置于横向滚动区或详情视图。
- 分页要显示当前位置、总量或“下一页是否存在”；加载下一页时不清空已显示内容。
- 详情面板关闭后应回到原列表位置和筛选条件。

### 5.4 状态组件

每一个异步区域都必须定义正常、加载、空、失败、无权限、成功/完成和不可用状态：

| 状态 | 必须内容 |
| --- | --- |
| 加载 | 正在获取的对象；布局尺寸稳定，避免内容跳动 |
| 空 | 无数据的业务原因与可执行入口，例如调整筛选或完成导入 |
| 失败 | 可理解的错误说明、请求号（可用时）与重试/返回/联系管理员入口 |
| 无权限 | 当前角色缺少的权限，不泄露受限数据或操作细节 |
| 成功 | 完成对象、结果摘要和下一步链接 |
| 不可用 | 依赖未满足的原因，例如数据质量未通过或运行尚未完成 |

状态消息容器应使用 `role="status"` 或合适的实时区域。通知不能在用户尚未阅读前自动消失；关键错误和审核结果须保留在页面中。

### 5.5 审核、发布与人工确认

人工计划确认、策略发布、任务重试和类似操作必须展示：目标对象、当前版本或状态、操作人的决定、必填备注、提交状态和服务端返回结果。确认成功只能表述为“记录人工决定”“发布已受理”等真实结果；不得表述为下单成功、自动执行或保证收益。

## 6. 页面模板与现有页面映射

| 页面模板 | 现有页面 | 核心结构与重点 |
| --- | --- | --- |
| 登录 | 登录 | 最小干扰布局、凭据校验、会话失败和返回路径 |
| 概览 | 运行总览 | 三列关键状态、异常优先、进入下一任务的链接 |
| 列表与检索 | 数据质量、股票池与日线、人工计划、人工成交、管理与审计 | 筛选、状态表格、分页、详情或行级处理 |
| 表单与结果 | 授权行情导入、新建回测、执行日终、策略草稿 | 前置条件、字段校验、执行反馈、结果链接 |
| 详情与报告 | 回测详情、日报、报告与偏差 | 数据版本、可用性、指标解释、明细与回溯 |
| 审核工作台 | 人工计划确认、策略审核 | 证据、决定、备注、审计结果与权限提示 |

新增页面必须先选择一个模板。若一个页面同时包含列表和编辑，默认以列表为主视图，将编辑放在详情面板、抽屉或独立页面，避免在同一首屏堆叠两个相互竞争的主任务。

## 7. 安全、权限与人工流程表达

- 所有页面保留“研究用途；不构成投资建议；仅支持人工确认与人工成交记录，不自动下单”的系统级边界。
- 行情导入、数据质量、日报、回测和报告需明确数据来源、数据批次或模拟属性；模拟价不是委托价。
- 管理、导入、执行日终、确认计划、发布策略等高权限任务，必须先展示当前权限或服务端授权结果。
- 前端不得根据本地角色或缓存直接放行受限操作；隐藏控件仅改善体验，服务端 RBAC 是最终约束。
- 所有可能造成业务状态变化的反馈，应展示请求号或可追溯结果标识（服务端提供时）。

## 8. 新页面接入流程

1. 写明用户任务、数据前置条件和安全边界。
2. 选择第 6 节中的页面模板；若无合适模板，先扩展本规范。
3. 从第 3 至第 5 节选择已有令牌、布局和组件，禁止为单页创造新的主色、间距体系或交互语义。
4. 为正常、加载、空、失败、无权限、成功和不可用状态补全设计与实现。
5. 按第 9 节完成桌面与移动端验收，并为权限、审批和状态转换补充自动化测试。

## 9. 上线验收清单

每次新增或改造页面，评审者必须逐项确认：

- [ ] 页面标题、业务说明和主操作符合页面模板，且主操作不超过一个。
- [ ] 研究用途、模拟属性、人工确认边界和权限表达与实际业务行为一致。
- [ ] 已使用规定的色彩、间距、字体、边框和圆角；不存在装饰性渐变或大圆角卡片。
- [ ] 表格、日期、数值、状态和缺失值格式一致；宽内容在小屏幕可控滚动。
- [ ] 加载、空、失败、无权限、成功和不可用状态都具备内容与恢复路径。
- [ ] 表单字段有标签和错误提示；提交防重复；危险操作展示对象、影响和备注。
- [ ] 键盘可达、焦点可见、实时状态可被辅助技术读取，且颜色不是唯一提示。
- [ ] 已在桌面和移动视口检查文本截断、遮挡、横向溢出与点击区域。
- [ ] 涉及权限、审核、发布、执行或幂等的页面，关键路径已有功能回归测试。

## 10. 附录：实现令牌

实现时应优先扩展现有 CSS 变量，而非在页面内新增硬编码值。建议保留如下名称：

```css
:root {
  --ink: #17212b;
  --muted: #5d6b78;
  --line: #d9e0e7;
  --accent: #185adb;
  --danger: #b42318;
  --ok: #16704a;
  --bg: #f4f6f8;
}
```

组件和页面实现应复用这些令牌与既有的 `page-heading`、`panel`、`form-grid`、`filters`、`table-wrap`、`actions`、`state`、`pagination` 等结构。新增通用样式应写在系统级样式中；业务页面只负责组合，不应私自覆盖全局语义。

## 11. 2026-09 渐进式统一基线

当前统一实现以 `static/css/app.css` 为唯一语义令牌层，以 `static/css/research-pages.css` 组合研究工作台样式。历史 prototype 样式不再加载，页面不得恢复独立的颜色、宽度、控件高度或圆角体系。

响应式验收按 `1440×900`、`1024×768`、`700×900` 和 `390×844` 执行。小于 `900px` 时使用 `#nav-toggle` 控制 `#main-nav` 的折叠状态；移动端页面保留 `16px` 主内容留白，只有 `.table-wrap`、代码块和 JSON 允许局部横向滚动。主题只改变令牌值，不在页面或组件内直接指定浅色面板。

页面迁移顺序为：全局框架与登录 → 数据质量/策略/回测/报告 → 总览与列表 → 导入/日终/审核/人工记录。每一批迁移都必须保留既有 `id`、`data-page`、`data-api-url`、表单字段名和权限/幂等行为，并通过页面契约与前端状态测试后再进入下一批。
